# 情报数据接口说明

本文件用于 A 成员对接 B 成员输出的结构化情报数据。

## 1. 交付目录

所有数据文件统一放在项目根目录的 `data/output/` 下。

## 2. 文件说明

| 文件 | 用途 |
| --- | --- |
| `sample_intel.jsonl` | 格式样例，用于联调确认 |
| `structured_intel.jsonl` | 基础结构化情报 |
| `enriched_intel.jsonl` | 六维富化后的情报 |
| `remediation_kb.json` | 修复知识库 |

## 3. 数据格式

JSONL 格式：每个文件一行一个 JSON 对象，UTF-8 编码。

示例：

```json
{"intel_id": "CVE-2026-85180", "source": "nvd", "title": "CVE-2026-85180", "description": "漏洞描述", "publish_time": "2026-09-26T12:00:00Z", "raw_url": "https://nvd.nist.gov/vuln/detail/CVE-2026-85180", "ai_relevant": true, "enrichment": {"cvss": {"score": 9.8, "severity": "CRITICAL"}, "poc": {}, "affected_assets": {}, "related_papers": [], "attack_chain": [], "remediation": null}}
```

## 4. 顶层字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `intel_id` | string | 唯一标识，例如 CVE 编号 |
| `source` | string | 数据来源，例如 `nvd`、`ghsa`、`cisa` |
| `title` | string | 情报标题 |
| `description` | string | 漏洞描述 |
| `publish_time` | string | 发布时间，ISO 8601 UTC |
| `raw_url` | string | 原始情报链接 |
| `ai_relevant` | boolean | 是否 AI 安全情报。`true` 为 A-E 类，`false` 为 F 通用安全情报 |
| `tags` | array | 标签数组，格式见第 8 节标签树 |
| `fingerprint` | string | 去重指纹，MD5 |
| `last_check_time` | string | 最近一次采集时间，ISO 8601 UTC |
| `enrichment` | object | 富化内容，见下文 |

## 5. enrichment 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `cvss` | object | CVSS 评分：`score`、`vector`、`severity`、`source`、`confidence` |
| `poc` | object | POC 信息：`repo_url`、`file_path`、`code_snippet`、`status` |
| `affected_assets` | object | 受影响资产：`exposed_count`、`top_countries`、`sample_ips`、`query_time` |
| `related_papers` | array | 相关论文列表 |
| `attack_chain` | array | 攻击链步骤列表 |
| `remediation` | object | 修复建议 |

### 5.1 related_papers 元素

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | string | 论文标题 |
| `arxiv_id` | string | arXiv 链接（entry id，完整 URL） |
| `authors` | array | 作者姓名列表（最多 5 个） |
| `abstract` | string | 论文摘要 |
| `similarity_score` | number | 与情报的语义相似度，范围 0.0 - 1.0 |

### 5.2 attack_chain 元素

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `tactic` | string | 攻击战术，例如 `Initial Access`、`Execution` |
| `technique_id` | string | 技术编号，ATT&CK 为 `TXXXX`，AI 场景使用 MITRE ATLAS `AML.TXXXX` |
| `technique_name` | string | 技术名称，例如 `Exploit Public-Facing Application` |
| `description` | string | 该攻击步骤在本漏洞场景下的说明 |

## 6. 枚举值约定

- CVSS `severity`：`CRITICAL`、`HIGH`、`MEDIUM`、`LOW`
- CVSS `confidence`：`high`、`medium`、`low`
- POC `status`：`unverified`、`success`、`failed`
- remediation `status`：`official_patch`、`temporary_mitigation`

## 7. 时间与空值约定

- 时间统一使用 UTC，格式：`2026-09-26T12:00:00Z`
- 空字符串字段使用 `null`
- 空列表字段使用 `[]`
- 暂无富化结果的子对象使用 `null`

## 8. 标签树

每条情报按成员 C 的规范打标，`tags` 数组包含：二级标签、一级分类、一级分类中文名、命中的组件名。

示例：

```json
{"tags": ["A1", "A", "AI基础设施与框架风险", "ollama"]}
{"tags": ["F", "通用安全情报"]}
```

### 8.1 一级分类

| 编号 | 名称 |
| --- | --- |
| A | AI基础设施与框架风险 |
| B | 模型与数据安全风险 |
| C | AI应用与智能体风险 |
| D | AI供应链风险 |
| E | AI安全政策与标准 |
| F | 通用安全情报 |

### 8.2 二级标签

| 一级 | 二级 |
| --- | --- |
| A | A1 推理框架、A2 训练/微调框架、A3 向量库/检索组件、A4 编排/Agent框架、A5 运行时/加速/容器 |
| B | B1 提示注入/越狱、B2 数据投毒/后门、B3 模型窃取/对抗、B4 隐私与合规 |
| C | C1 Agent工具滥用、C2 RAG风险、C3 AI应用漏洞、C4 自主决策风险 |
| D | D1 依赖库漏洞、D2 模型权重/数据集、D3 容器/镜像、D4 API/服务 |
| E | E1 政策法规、E2 标准规范、E3 学术论文、E4 行业报告 |
| F | F1 通用漏洞、F2 通用攻击事件、F3 通用工具/技术 |
